# 校准样本（WorkBuddy 锚点）

效果以这些「一段指令」为准，不要编回带标题的工单。

## 1. 周报

草稿：`帮我写本周周报`

差：资深人设 + 十二段周报模板；或【问题】【目标】【完成标准】工单。

好（方向）：

```text
请汇总本周工作进展，按事项写成可直接发送的周报：每条写清结果（不要只写「跟进中」），标出风险和需要谁拍板，并列出下周计划。全文一页内。
```

验收：中文；含「周报」类词；补了结构/输出；≠ 原文；未编造具体销售数字。

## 2. 解释代码（原版 few-shot）

草稿：`请帮我解释这段代码的功能`

好：

```text
请解释这段代码的主要功能、执行流程和关键逻辑，并指出可能需要注意的边界情况。
```

验收：仍是「请解释…」的指令，不是真的开始解释代码。

## 3. 英文（原版 few-shot）

草稿：`Please explain what this code does`

好：

```text
Explain what this code does, including its main purpose, key control flow, and any important edge cases.
```

验收：全程英文；含 purpose / flow / edge cases 语义。

## 4. 中英混合（原版 few-shot）

草稿：`这段代码有 bug，can you help me fix it?`

好：

```text
请分析这段代码中的 bug，explain the root cause, and provide a minimal fix with necessary verification steps.
```

验收：中英都保留，不要统一翻译成一种语言。

## 5. 缺对象也不编造

草稿：`把字体调大一点`

好：

```text
请把当前界面/文档里的正文字号调大一档，只改字体大小和必要的行高，不改配色、布局和文案。若存在多处文字层级，以正文为准并保持标题相对层级。
```

差：编造 `App.tsx`、`index.css`、具体像素值（原文没有）。

## 6. 产品口语

草稿：`这个登录页有点乱，帮我优化一下，最好别动接口`

好：

```text
请整理当前登录页的信息层级和文案，让主操作（登录）一眼可完成，并补全错误提示的下一步说明。不要改后端接口、请求字段、路径和鉴权，不要加第三方登录，也不要重做整站设计系统。
```

## 不要编进增强结果的

除非草稿里已有：部署、CI、README、SOLID、新依赖、未点名的框架（不要学系统提示词里「狗网站 → Next.js」那个锚点去加技术栈）、对原问题的回答。
